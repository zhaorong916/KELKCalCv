## 2026-10-16 P1 复核：复合键补全（trim_type / stroke_value 入键）与 18 系列全量复核

### 背景

用户在各机型比对报告章节标题上手写批注指出：**同一复合键出现多行 = 复合键不完整**。主要问题：GC120/GC210/GV120/GV130/GA510 的 `trim_type` 未入键，GC320 的 `stroke_value` 未入键，以及 GZ800 多系列共用 adapter 被混在 GZ810 一个报告中。

### 修复方案

**1. 复合键策略 (`SERIES_KEY_STRATEGY`)**

- GC120/GC210/GV120/GV130/GA510：键增加 `trim_type`，消除一对多
- GC320：键增加 `trim_type` + `stroke_value`（多级阀同 dn/trim 多个行程点）
- GV110：`(series,trim,flow_char)` → `(series,trim,flow_char,trim_type)`（不含 dn，库中 15A/20A/25A 共享 trim 行）

**2. 命名归一化 (`normalize_adapter_row`，比对与入库共用)**

- `Md EQ%` → `EQ%`，并联动将 trim_type 改写为 Large Cv / Modified（GC120/GV120=Large Cv，GC210=Modified）
- GV120：`P-port→Standard`、`Q-port→ON-OFF`；GA510：`High Performance P-port→Standard`
- GV130：`P-port High EQ→Standard`、`P-port Large Cv→Large Cv`、`Q-port→ON-OFF`
- GV110：仅保留 `Needle→Standard`；V-type 库中无数据，保留原值计入新增；另修正 `1A + plug_mm=1.6 → 1.6A`
- GC120/GC210：`Full→Standard`

**3. 重复键处理**：同键同 Cv 视为良性别名重复（GV110 多 dn 折叠）静默跳过；仅同键不同 Cv 记入「复合键冲突告警」章节。修复后全部系列键冲突 = 0。

**4. 入库脚本对齐 (`import_validated_data.py`)**：upsert 查找条件直接复用各系列比对复合键（stroke_value 为 None 时生成 IS NULL），入库前同样执行 `normalize_adapter_row`，消除旧逻辑中 GV120 seat_type Metal vs NULL、GV110 dn 为空导致的误判 insert。

**5. GZ800 多系列拆分**：GZ810/820/830/840/850/860 共用一个 adapter，`parse_rated_cv()` 返回全部系列行。比对与入库改为：系列清单从注册表全量取（preferred 顺序 + 新注册系列），并按每行 `series_code` 过滤；GZ820~860 沿用 GZ810 的归一化与键策略（EQ%→Linear、Downstream→Standard、dn None→15A）。

**6. 人工批注沿用机制**：重跑报告前提取旧标题 `——xxx`，写入新标题为 `前缀——xxx（上版人工标注）`；章节消失的批注自然脱落（如 GC120 旧「多余」章节），重复重跑不会累积后缀。

## 2026-10-16 P1 复核：基于新库表结构 (stroke_value/stroke_unit) 重新生成全部比对报告

### 背景

`valve_cv_stk` 表字段重命名（`stroke`→`stroke_unit`、`stroke_mm`→`stroke_value`）完成后，按新库表结构复核所有数据比对报告。

### 发现的问题

5 个系列出现「0 一致 / 全部新增 + 全部多余」，根因是 adapter 与库中的**命名约定不一致**（非 stroke 重命名引起）：

| 系列 | Adapter 约定 | 库中约定 |
|---|---|---|
| BT110 | flow_char=60°/90°, trim_type=Damper/15 Deg Sealed | flow_char=Inherent Character, trim_type=Standard, 密封在 seat_type |
| BT310 | flow_char=60°/90° | flow_char=Inherent Character |
| BV130 | flow_char=Inherent Character, trim_type=Full Bore | flow_char=ON-OFF, trim_type=ON-OFF |
| GV110 | flow_char=EQ%, trim_type=Needle/V-type | flow_char=Linear, trim_type=Standard |
| GZ810 | flow_char=EQ%, trim_type=Downstream/Upstream, dn=None | flow_char=Linear, trim_type=Standard, dn=15A |

另：BT110 库中 15 Deg Sealed 数据 stroke_value=75（15° 密封蝶阀最大开度 75°），与 adapter 的 90° Sealed Cv 为同一数据点。

### 修复方案 (compare_cv_data.py)

1. 新增 `FLOW_CHAR_NORMALIZE`、`DN_LABEL_NORMALIZE` 映射，扩展 `TRIM_TYPE_NORMALIZE`
2. 新增 `normalize_adapter_row()` 统一归一化入口（含 BT110 Sealed 90°→75° 特殊处理），仅用于比对，不影响入库
3. 键策略调整：
   - BT110: + `seat_type` + `stroke_value`
   - BT310: + `stroke_value`
   - GV110: 去掉 `dn_label`（库中同一 trim 对应 3 个 DN）
   - GZ810: + `trim_type`（区分 Downstream/Upstream）

## 2026-10-15 P1 修复：BT210/BV210 比对报告不完整

### 问题

BT210 数据比对报告不完整：80 行 adapter 数据只有 20 行被分类，其余 60 行未被分类。

### 根因分析

1. **匹配键不完整**: 宽松键只用了 `(series_code, dn_label, trim_label, flow_char)`，忽略了 `pressure_rating` 和 `trim_type`
2. **trim_type 命名不一致**: 
   - BT210 库中 `trim_type="Standard"`（实际是 90° 开度），adapter 输出 `"90° Open"`
   - BV210 库中 `flow_char="ON-OFF"`，adapter 输出 `"Inherent Character"`
   - BV210 库中 `pressure_rating="300#"`，adapter 输出 `"150#/300#"`
3. **80 行 adapter 数据只有 20 个唯一键**，导致 60 行被覆盖，无法比对

### 修复方案

1. **基于系列的匹配键策略** (`SERIES_KEY_STRATEGY`):
   - 蝶阀 BT210/BT110/BT310: 包含 `trim_type`（区分 60°/90° 开度）
   - 球阀 BV210: 包含 `trim_type` + `pressure_rating`
   - 直行程调节阀: 仅用 `(series_code, dn_label, trim_label, flow_char)`

2. **trim_type 标准化映射** (`TRIM_TYPE_NORMALIZE`):
   - BT210: `"90° Open"` → `"Standard"`, `"60° Open"` → `"60°"`

3. **修正 adapter 输出**:
   - BV210: `flow_char` 改为 `"ON-OFF"`, `trim_type` 改为 `"Standard"`, `pressure_rating` 改为 `"300#"`/`"600#"`

4. **重复键处理**: 当多个行有相同键但不同 Cv 值时，用 `|cv=<值>` 作为附加键区分

### 规则构成（117 条）

| category | priority | 数量 | 要点 |
|---|---|---|---|
| scope | 10 | 53 | 阀型决策树（`series_category`/`valve_action`）、温度分档（`low_temp`/`high_temp`）、系列口径/工况排除 |

### 四阶段流水线（`selector.py`）

1. **scope(10)**：取 `ValveType.is_active==True` 全量系列，应用 scope 规则（`exclude`/`require`）过滤
2. **constraint(20)**：对存活系列按 `valve_cv_stk` 分组构造候选（口径/阀芯/特性/压力等级），应用 constraint 规则 + 可调比硬校核 + 阀体材质温压插值校核 + 最大允许压差告警
3. **preference(30)**：对候选打分（`boost`/`penalty`），累计 `score` 与 `applied_rules`
4. **post_filter(40)**：`set_field`/`flag` 补字段、开度窗口 `penalty`、汇总 `warnings`
- 排序：`(-score, |opening-70|, rated_cv)`，输出 `rank`

### 关键实现点

- **受限条件求值** `match_condition`：仅支持 `{key: {op: value}}` 白名单比较，**禁 eval/exec**；未知键/未知算子 → 追加 warning 且视为不匹配。算子：`_eq/_ne/_min/_max/_gt/_lt/_required/_or`，多键按 `and`/`or` 组合，同键多算子按 AND。
- **开度语义 = 曲线图 %Stk（用户确认）**：`phi = Cv_required / rated_cv` → 按 `stroke_mode` 反解为 %Stk，`opening = %Stk × 100`。移植前端 `Calculation.vue::evalEqcv`（`selector.py::_cv_ratio_to_stk`），覆盖 `linear/ln_eqn/exp_formula/poly_cv_div100/poly_phi100_div100/poly_cv_div_angle/poly_div60/eq_index` 全部分支。
- **复用既有引擎**：Cv 反算用 `calc/engine.py::calculate_case`；曲线（`stroke_mode`/`eqcv`/`fstk`/`divisor`/`fd_mode`）复用 `api/valve_types.py::_get_curves_by_selection_impl`（懒加载避免 api←→calc 导入环），不重复实现 stroke_mode 判定。
- **规则缓存**：`_rules(category)` 一次性查全部 `SelectionRule`，Python 侧按 `category`+`is_active` 过滤并缓存；`condition_expr`/`action_payload` 为 JSON **字符串**，经 `_ParsedRule` 解析为 dict 后匹配。
- **软删**：`is_active=False` 的规则不参与匹配（已单测覆盖）。

### 关键决策：rule_code UNIQUE → 原地 upsert

`selection_rules.rule_code` 有 UNIQUE 约束，无法「旧版软删 + 新行插入」两条同 code 共存。故 P2 seed 采用**按 `rule_code` 原地 upsert**；版本化留待 P5 规则管理 UI 阶段。已同步至 [P2 实施计划](../../.trae/documents/P2_规则库与匹配引擎实施计划.md) 2.1 节。
