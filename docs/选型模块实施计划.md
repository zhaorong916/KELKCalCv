### 0.3 工程基线

| 事项 | 现行实践 | 实施约束 |
|---|---|---|
| 建表方式 | `main.py` lifespan 中 `Base.metadata.create_all(checkfirst=True)` | 新表自动创建；已有表加列需独立脚本 |
| 迁移工具 | 无 Alembic 迁移链 | 不引入 Alembic，增列用一次性脚本 |
| Seed 模式 | ① lifespan 内置 seed 函数；② backend 根目录独立脚本 | 结构性字典数据用①；样本提取数据用② |
| DDL 同步 | — | 每次表结构变更必须同步 `models/__init__.py` + `schemas/__init__.py` |
| 数据库 | SQL Server 192.168.1.112 | 禁全表 DELETE；upsert 幂等 |
| 安全红线 | — | 禁全表 DELETE / 禁凭据入文档 / 禁跳过校验 / 禁违反 series_code 唯一约束 |
| PDF 提取 | pdf2docx → python-docx（17 系列已验证） | 统一 adapter 模式 |

## P1 数据入库与校验【预估 7 人天】

> 核心原则：`valve_cv_stk` 为唯一权威 Cv 数据源；新提取数据用于**校验→标注差异→人工确认→以样本为准**。adapter 模式保证逐系列映射准确。

### 任务 1.1 系列 adapter 模板【1 天】

- **涉及文件**：新建 `backend/app/data_adapters/__init__.py`、`base.py`
- **步骤**：
  1. 定义 `SeriesAdapter` 基类：`series_code`、`parse_rated_cv()`、`parse_allowable_dp()`、`parse_body_pt()`、`parse_dimensions()`
  2. 元数据注册：全局 adapter 注册表 `ADAPTERS = {"GC120": Gc120Adapter, ...}`
  3. 通用工具：JIS A → dn_mm 换算、英寸分数解析、温度范围解析
- **验证**：基类可被具体 adapter 继承；`ADAPTERS.keys()` 覆盖 12 个阀体系列

### 任务 1.2 首批 6 系列 adapter（高覆盖率）【2 天】

- **覆盖系列**：GC120/210、GC320、GV120、BT210、BV210、GA510
- **涉及文件**：`backend/app/data_adapters/gc120_adapter.py`、`gc320_adapter.py`、`gv120_adapter.py`、`bt210_adapter.py`、`bv210_adapter.py`、`ga510_adapter.py`
- **步骤**：每系列编写 adapter 实现 4 个 parse 方法，解析对应 `docs/<系列>_structured_data.json`
- **验证**：每个 adapter 的 `parse_rated_cv()` 输出行数与样本 Cv 表行数一致

### 任务 1.3 第二批 6 系列 adapter【2 天】

- **覆盖系列**：GV110、GV130、BT110、BT310、BV130、GZ800
- **步骤**：同 1.2
- **验证**：同上

### 任务 1.4 比对与差异报告【1 天】

- **涉及文件**：新建 `backend/compare_cv_data.py`、`docs/数据比对报告/`
- **步骤**：
  1. 读取库中 `valve_cv_stk` 全部记录
  2. 逐系列执行 adapter 解析，与库中记录按复合键比对
  3. 差异 > 5% 的行生成差异报告（`docs/数据比对报告/<系列>_diff.md`）
  4. 差异 ≤ 5% 的行自动标记「与库一致」
  5. 新系列（库中无记录）标记「全新入库」
- **验证**：差异报告完整，无未分类行

### 任务 1.5 人工确认与入库【1 天】

- **涉及文件**：`backend/import_validated_data.py`
- **步骤**：
  1. 差异报告交用户确认，标注「以样本为准」/「以库为准」/「需修正」
  2. 确认后 upsert 到 `valve_cv_stk`（已存在行更新、新增行插入）
  3. GC210 的 cv_min 字段从 GC120_210_structured_data.json 提取入库
  4. body_pt_ratings 从 GC120/210、GC320、GA510、BV130 等温压表入库
  5. allowable_pressure_drops 从各系列压差表入库
- **验证**：库中各系列 Cv 数据与确认后报告一致；cv_min 非空率 > 90%

**P1 验收标准**：17 系列 adapter 全部完成、差异报告归档、确认后数据入库、GC210 cv_min 回填完成。

假设从 2026-10-16 启动，按工作日排期（不含人工确认、用户评审等待）：

```
周次    10/16 10/19 10/26 11/02 11/09 11/16 11/23
        ├────┼────┼────┼────┼────┼────┼────┤
P0      ████
P1           ████████████████
P2                            ███████████
P3                                       ███████
P4                                              ███
P5                                                 ██
P6                                                    ████
```

| 阶段 | 起止（预估） | 工时 |
|---|---|---|
| P0 基础设施 | 10/16 ~ 10/19 | 2 天 |
| P1 数据入库与校验 | 10/20 ~ 10/28 | 7 天 |
| P2 规则库 + 引擎 | 10/29 ~ 11/05 | 6 天 |
| P3 API + 前端 MVP | 11/06 ~ 11/11 | 4 天 |
| P4 选型→计算贯通 | 11/12 ~ 11/16 | 3 天 |
| P5 规则管理 UI | 11/17 ~ 11/18 | 2 天 |
| P6 执行机构选型 | 11/19 ~ 11/24 | 4 天 |

**总周期：约 28 工作日 ≈ 6 周**（不含 P1.5 人工确认等待、P3 验收评审等待）

### 关键路径

- **P0 → P1 → P3 → P4** 是关键路径（18 天），任何一环延迟都会影响整体交付
- P2 可与 P1 并行，P5/P6 可与 P4 并行，不影响关键路径
- P1.5 人工确认是唯一的外部依赖，需预留 1~2 天等待时间
