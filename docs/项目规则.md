# KELKCalCv 项目规则

## 1. 服务器部署与更新

### 1.1 仓库与远程

| 角色 | 地址 |
|---|---|
| 主仓库（默认 fetch/pull） | https://gitee.com/KELKzhao/kelkcalcv.git |
| 备份仓库 | https://github.com/zhaorong916/KELKCalCv.git |
| 本地 `git push` 自动双推 | 同时推送到 gitee 和 github |

当前 remote 配置：
- `origin`：fetch 走 gitee，push 同时走 gitee + github
- `backup`：fetch/push 都走 github（独立备用）

### 1.2 部署脚本（`deploy/` 目录）

| 文件 | 用途 |
|---|---|
| `update.bat` | 从 gitee `git pull origin main` + `pip install -r requirements.txt` |
| `start-server.bat` | 启动 FastAPI（uvicorn 端口 8000），自动创建 venv 并装依赖 |
| `stop-server.bat` | 清理 8000 端口上所有 LISTENING 进程 |
| `bootstrap.bat` | 一键首次部署：环境检查 → 克隆仓库 → 生成 .env → 启动 |
| `部署说明.md` | 完整部署文档（环境要求/常见问题/安全须知） |
| `README.txt` | 简要的首次部署与日常更新步骤 |

**服务器更新安全保证**：`backend/.env` 已在 `.gitignore`，`update.bat` 的 `git pull` 不会覆盖服务器本地的数据库密码等敏感配置。

### 1.3 首次部署步骤

**推荐**：直接运行 `deploy\bootstrap.bat`（或部署包内同名脚本）自动完成下述 3~5 步；也可手动执行：

1. 服务器安装 Python 3.10+ 和 Git
2. 安装 ODBC Driver 17 for SQL Server（pyodbc 必需）
3. `git clone https://gitee.com/KELKzhao/kelkcalcv.git`
4. 复制 `backend/.env.example` → `backend/.env`，填入真实 DB 密码和 SECRET_KEY
5. 运行 `deploy\start-server.bat` 启动
6. 访问 http://localhost:8000

### 1.4 日常更新步骤

1. `deploy\stop-server.bat` → 停止
2. `deploy\update.bat` → 拉取 + 依赖同步
3. `deploy\start-server.bat` → 重启

## 2. 批处理文件编码规范

**所有 `.bat` 文件必须同时满足以下三条**，确保中文在 cmd 中正确显示：

1. **文件编码**：**UTF-8 with BOM**（`\xef\xbb\xbf` 开头）
   - BOM 帮助 cmd 识别 UTF-8 编码；Windows 10+ / Server 2016+ 均正确跳过 BOM 执行首行
   - 保存方式：VS Code 右下角 → "通过编码重新保存" → 选 **"UTF-8 with BOM"**
2. **行尾必须是 CRLF（\r\n）**
   - LF-only 的批处理在部分 cmd 版本上 goto/label 解析异常
3. **首两行必须是纯 ASCII**，第 2 行切换代码页：

   ```bat
   @echo off
   chcp 65001 >nul
   ```

   - 之后的中文字符串才按 UTF-8 解码显示
   - `>nul` 隐藏代码页切换提示

**生成方式**：推荐用 Python 脚本统一生成（`b"\xef\xbb\xbf" + text.encode("utf-8")`），避免编辑器误转编码。

**⚠️ 历史教训（2026-10-20）**：曾出现"UTF-8 无 BOM"方案导致 cmd 按 GBK 解析中文产生乱码，根因是**编辑器将 UTF-8 文件误读为 GBK 后重新保存**，中文变成 U+FFFD 替换字符。BOM 本身不会导致首行报错（实测 Windows 10 cmd 正常执行）；真正的问题是内容被污染。故恢复 BOM 方案，并强调：**任何情况下不要用编辑器"另存为 ANSI/GBK"处理 .bat 文件**。

**禁止事项**：
- 禁止用 LF 行尾保存 .bat（goto/label 可能解析异常）
- 禁止用 GBK/ANSI 编码保存 .bat 文件（跨语言 Windows 会乱码，且编辑器误转会导致 U+FFFD 污染）
- 禁止在 chcp 65001 生效前（首两行）出现任何中文

## 3. 脱敏红线（四大约束补充）

除已确立的「四大红线」外，新增以下凭据脱敏规则：

| 位置 | 规则 |
|---|---|
| `backend/.env.example` | 数据库密码、SECRET_KEY 用 **`<placeholder>`** 占位符，禁止出现真实值 |
| `backend/app/core/config.py` | `Settings` 类中 DB_HOST / DB_USER / DB_PASSWORD / SECRET_KEY 等敏感字段**默认值必须为空串**（生产环境由 `.env` 注入） |
| 项目文档（README.md / docs/*.md / .trae/documents/*.md） | 禁止写入任何真实凭据（密码、密钥、连接串） |
| `.env` 文件 | 必须在 `.gitignore` 中排除（已生效） |

**已修复案例**：2026-10-19 发现 `.env.example` 与 `config.py` 默认值含真实 SQL Server 密码（此处已按本红线隐去），已脱敏为占位符并提交推送。

## 4. 已确立的四大红线（继承，不可突破）

1. **禁全表 DELETE**：数据脚本不得执行 `DELETE FROM <table>`；清理用 `--batch-size` 分批
2. **禁凭据入文档**：任何文档不得出现真实密码、密钥、连接串（详见上节）
3. **禁跳过校验**：数据入库前必须 dry-run，校验匹配键、字段类型、空值
4. **禁违反 `valve_types.series_code` 唯一约束**：seed/upsert 必须按 `series_code` 命中更新，禁止 INSERT 冲突

## 6. 编码与实现约定

- **数据库**：统一 SQL Server（192.168.1.112），会话 `SessionLocal` 来自 `app.core.database`，`autoflush=False`，插入后需显式 `db.flush()`
- **测试**：unittest（无 pytest 依赖），运行 `python -m unittest tests.<module>`
- **导入环防护**：`app.api` 与 `app.calc` 互调时采用函数内懒加载（`from app.xxx import Y` 放在函数体）
- **命名**：系列代码统一大写（`GC120`、`GV130`），别名仅用于曲线映射（`BC120→BC110`）
