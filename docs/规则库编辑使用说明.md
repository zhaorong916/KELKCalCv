# 选型规则库编辑 · 使用说明

本文档面向规则维护人员，介绍「选型规则库」页面的各项操作：查看、筛选、新建、编辑、启用/停用、删除，以及条件表达式的三种录入方式。

---

## 1. 页面入口

在系统顶部导航进入 **选型规则库** 页面。页面由三部分组成：

1. **筛选条** — 按类别 / 目标系列 / 状态 / 关键词过滤规则
2. **规则表格** — 展示规则列表，支持展开查看详情
3. **底部统计** — 各类别规则数量与当前筛选匹配数

---

## 2. 规则编号说明

规则编号（`rule_code`）由系统自动生成，**不可手工修改**，格式为：

```
R-{类别缩写}-{系列}-{三位序号}
```

| 类别 | 缩写 | 示例 |
|---|---|---|
| 适用范围 scope | SCOPE | `R-SCOPE-GC120-001` |
| 硬约束 constraint | CON | `R-CON-GLOBAL-002` |
| 工况偏好 preference | PREF | `R-PREF-BT110-003` |
| 后处理 post_filter | POST | `R-POST-OPEN-004` |

- 目标系列为 `*`（全局）时，编号中写作 `GLOBAL`
- 序号按「类别 + 系列」分组递增，新建时自动取当前最大序号 +1

> 新建规则时，编号输入框为禁用状态，placeholder 会根据已选类别和目标系列实时显示预览（如 `R-SCOPE-GC120-***`），保存后由后端生成最终编号。

---

## 3. 筛选规则

顶部筛选条支持以下条件，可组合使用：

| 筛选项 | 说明 |
|---|---|
| 类别 | 适用范围 / 硬约束 / 工况偏好 / 后处理 |
| 目标系列 | 下拉选择已有系列，或输入自定义系列；`*` 表示全局 |
| 状态 | 启用 / 停用 |
| 关键词 | 模糊匹配 rule_code / 规则名称 / 来源参考 |

点击「重置」清空所有筛选条件。

---

## 4. 查看规则详情

点击表格行左侧的 **展开箭头**，可查看该规则的完整信息：

- `rule_code` — 规则编号
- `condition_expr` — 条件表达式（格式化 JSON）
- `action_payload` — 动作参数（格式化 JSON）
- `source_ref` — 来源参考
- 创建时间 / 更新时间

---

## 5. 新建规则

点击页面右上角 **+ 新建规则**，弹出新建对话框。

### 5.1 基础字段

| 字段 | 必填 | 说明 |
|---|---|---|
| 规则编号 | — | 系统自动生成，不可编辑 |
| 规则名称 | ✅ | 一句话说明规则作用（≤128 字） |
| 类别 | ✅ | scope / constraint / preference / post_filter |
| 目标系列 | | 下拉或自定义输入；`*` 表示全局（默认） |
| 动作 | ✅ | 见下方动作说明 |
| 优先级 | | 1–99，数字越小越先执行；切换类别会自动填入默认优先级 |
| 条件组合 | | and（全部满足）/ or（任一满足） |
| 启用 | | 开关，关闭后规则不参与选型 |
| 来源参考 | | 如 `GC120_210:p4`，便于追溯规则出处 |

### 5.2 动作（action）说明

| 动作 | 含义 | action_payload |
|---|---|---|
| exclude | 排除候选（满足条件的候选被剔除） | 无需参数，留空 `{}` |
| require | 硬性要求（候选必须满足） | 无需参数，留空 `{}` |
| boost | 加权加分 | `{"score": 90}` |
| penalty | 扣分 | `{"score": -30}` |
| set_field | 回填字段 | `{"field": "fd_mode"}` |
| flag | 标记 | 无需参数，留空 `{}` |

### 5.3 条件录入的三种方式

对话框「辅助录入」提供三种模式，切换时互不影响，最终都写入下方的「条件表达式 JSON」：

#### 方式一：自然语言（推荐）

在文本框输入中文描述，点击「本地解析」或「AI 解析」：

- **本地解析**：前端正则解析，无需网络，支持常见句式
- **AI 解析**：调用大模型解析更复杂的描述；若后端未配置 `LLM_API_KEY`，自动回退到本地解析

**支持的句式示例：**

```
BT110 在设计温度低于 -5℃ 时排除
GC210 在空化或闪蒸时加 30 分
设计温度不低于 -20 且不高于 200
介质为液体且泄漏等级为 IV
压力超过 1000 kPa 时排除
口径在 DN50 到 DN300 之间
```

**支持的关键词：**
- 比较：低于 / 小于 / 高于 / 大于 / 不低于 / 不小于 / 不高于 / 不大于 / 等于 / 不等于
- 区间：`-20 到 200`、`50 到 300`
- 枚举：介质（液体/气体/蒸汽/两相）、流态（空化/闪蒸/阻塞流/正常）、泄漏等级（IV/V/VI）、阀门作用（气关/气开）
- 布尔：NACE 要求、防火认证、无铜要求、低温工况、高温工况

解析成功后会显示预览（目标系列、类别、动作、条件描述），确认无误后保存。

#### 方式二：条件行

逐行填写条件，每行包含：**字段 + 算子 + 值**。

- **字段下拉框**：按「数值 / 枚举 / 布尔」分组，同物理量的下限/上限键已加后缀区分（如「设计温度（下限）」「设计温度（上限）」）
- **算子下拉框**：`= 等于` / `≠ 不等于` / `≥ 不低于` / `≤ 不高于` / `> 高于` / `< 低于` / `属于其一`
- **值**：数值直接填数字；枚举填数据库取值（如 `liquid`、`空化`、`VI`）；布尔填 `true` / `false`

点击「+ 添加条件」增加行，「删除」移除行，「同步到 JSON」将所有行写入下方条件表达式。

#### 方式三：关闭辅助

直接在「条件表达式 JSON」文本框中手写 JSON。

## 6. 条件表达式 JSON 规范

### 6.1 基本结构

条件表达式是一个 JSON 对象，键为条件字段，值为比较算子 + 数值：

```json
{
  "temp_min": { "_lt": -5 },
  "media": { "_eq": "liquid" },
  "nace": { "_required": true }
}
```

多个键之间的逻辑关系由「条件组合」（`and` / `or`）决定。

### 6.2 可用字段

**数值类：**

| 字段 | 含义 | 单位 | 说明 |
|---|---|---|---|
| `temp` / `temp_min` / `temp_max` | 设计温度 | ℃ | 等值 / 下限 / 上限 |
| `p1` / `p1_max` | 阀前压力 | kPa | 等值 / 上限 |
| `dp` / `dp_max` | 压差 | kPa | 等值 / 上限 |
| `dp_ratio` / `dp_ratio_max` | 压差比 | — | 等值 / 上限 |
| `pipe_size` / `pipe_size_min` / `pipe_size_max` | 公称通径 | mm | 等值 / 下限 / 上限 |
| `cv_required` | 所需 Cv | — | — |
| `rated_cv` / `cv_min` / `cv_max` | 额定 Cv | — | 等值 / 下限 / 上限 |
| `opening` | 开度 | % | — |
| `rangeability` / `rangeability_required` | 可调比 | — | 等值 / 要求 |

**枚举类：**

| 字段 | 取值 |
|---|---|
| `media` | `liquid` / `gas` / `steam` / `twophase` |
| `flow_regime` | `空化` / `闪蒸` / `阻塞流` / `正常` |
| `leakage_class` | `IV` / `V` / `VI` |
| `valve_action` | `FC`（气关）/ `FO`（气开） |
| `series_category` | 系列类别 |
| `series_product_line` | 产品线 |

**布尔类：**

`nace`、`fire_safe`、`copper_free`、`low_temp`、`high_temp`

### 6.3 算子

| 算子 | 含义 | 示例 |
|---|---|---|
| `_eq` | 等于 | `{"media": {"_eq": "liquid"}}` |
| `_ne` | 不等于 | `{"flow_regime": {"_ne": "正常"}}` |
| `_min` | ≥（不低于） | `{"temp_min": {"_min": -20}}` |
| `_max` | ≤（不高于） | `{"temp_max": {"_max": 200}}` |
| `_gt` | >（高于） | `{"p1": {"_gt": 1000}}` |
| `_lt` | <（低于） | `{"temp_min": {"_lt": -5}}` |
| `_required` | 有此属性（布尔） | `{"nace": {"_required": true}}` |
| `_or` | 属于其一 | `{"media": {"_or": ["liquid", "gas"]}}` |

### 6.4 多分支逻辑（`$and` / `$or`）

对于复杂的分支条件，可使用 `$and` / `$or` 嵌套数组：

```json
{
  "$or": [
    { "temp_min": { "_lt": -5 } },
    { "temp_max": { "_gt": 200 } }
  ]
}
```

含义：温度低于 -5℃ **或** 高于 200℃。可多层嵌套。

### 6.5 格式化

点击 JSON 文本框下方的「格式化」按钮，可自动美化 JSON 缩进，便于阅读。

## 7. 编辑规则

在表格操作列点击「编辑」，弹出编辑对话框。

- **规则编号** 不可修改（保持历史追溯一致）
- 其余字段均可修改
- 修改条件后，「辅助录入」会切换到自然语言模式并回填中文描述，可直接改写后重新解析

---

## 8. 启用 / 停用规则

表格「启用」列的开关可直接切换规则状态：

- **启用**：规则参与选型计算
- **停用**：规则不参与选型，但保留在库中

> 停用是软操作，不会删除规则，适合临时下线某条规则。

---

## 9. 删除规则

在表格操作列点击「删除」，会弹出确认框。

⚠️ **删除限制**：若该规则已被选型记录（`SelectionRecord.applied_rule_ids`）引用，则不允许删除，系统会返回提示。此时应改为「停用」而非删除。

---

## 10. 注意事项

1. **编号自动生成**：新建时无需关心编号，系统按类别+系列分组递增
2. **条件键白名单**：条件表达式中的字段和算子必须在白名单内，否则保存时后端会报错
3. **动作参数**：`boost` / `penalty` 必须提供 `{"score": n}`；`set_field` 必须提供 `{"field": "字段名"}`；其余动作可留空 `{}`
4. **AI 解析**：需在后端 `.env` 中配置 `LLM_API_KEY`，否则自动回退到本地解析
5. **删除谨慎**：被选型记录引用的规则无法删除，请改用停用
6. **优先级**：数字越小越先执行；`exclude`（排除）和 `require`（要求）会立即生效，`boost` / `penalty` 按分数累加
